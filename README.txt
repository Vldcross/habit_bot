Бот привычек и накоплений

Python 3.12. Бот работает через long polling: отдельный постоянно запущенный
процесс получает сообщения Telegram. HTTP-сервер и открытый порт не нужны.

ЛОКАЛЬНЫЙ ЗАПУСК

1. Создайте окружение и установите зависимости:
   python3 -m venv .venv
   .venv/bin/python -m pip install -r requirements.txt

2. В настройках хостинга или переменных текущего процесса задайте:
   BOT_TOKEN — токен от @BotFather (не добавляйте его в Git или логи).
   DATA_FILE — полный путь к JSON-файлу на постоянном диске.
   Если DATA_FILE не задан, используется data.json рядом с bot.py.
   Файл .env автоматически не загружается; .env.example — пример имён.

3. Проверьте доступ без получения обновлений и отправки сообщений:
   PYTHON_BIN="$PWD/.venv/bin/python" ./start.sh --check

4. Запустите один экземпляр бота:
   PYTHON_BIN="$PWD/.venv/bin/python" ./start.sh
   Можно также использовать .venv/bin/python bot.py.

КАК ПОЛЬЗОВАТЬСЯ

/start создаёт цель по умолчанию. Повторный /start сохраняет прогресс.
«⚙️ Настройки» или /settings: название привычки, сумма в рублях, число дней.
Вводите целые положительные числа. /cancel отменяет незавершённые изменения.
Изменение настроек сохраняет накопленную сумму и уже отмеченные дни.
«Да» начисляет сумму один раз за календарный день по Москве.
«Нет» не меняет прогресс и не мешает позже отметить успешный день.
Статистика показывает накопления. По завершении цели начисления прекращаются.
/reset_all удаляет только вашу цель. Для новой цели затем нажмите /start.
Напоминания приходят в 21:00 Europe/Moscow, если день ещё не отмечен
и цель не завершена. Команды предназначены для личного чата с ботом.

ХОСТИНГ RENDER

Для постоянной работы выбран Background Worker с постоянным диском 1 ГБ.
Готовая конфигурация находится в render.yaml: один процесс, Python 3.12,
проверки перед запуском и DATA_FILE=/var/data/habit_bot/data.json.
Render управляет процессом и перезапускает его при падении.
Worker и диск платные; проверьте актуальную сумму в Render перед созданием.
Ни один сервис этой конфигурацией сам по себе ещё не создаётся.

1. Загрузите исправления вместе с render.yaml в репозиторий GitHub.
2. На https://dashboard.render.com/ выберите New + -> Blueprint
   и подключите этот репозиторий с веткой исправлений.
3. Через @BotFather перевыпустите ранее опубликованный токен и введите
   новый токен в поле BOT_TOKEN в Render. Не отправляйте его в чат.
4. Проверьте выбранный тариф и стоимость диска, затем создайте сервис.
5. После деплоя откройте Logs. Должны появиться сообщение о соединении
   с Telegram и запуск polling. Напишите своему боту /start и пройдите
   настройки; проверьте статистику и защиту от повторного «Да».

Конфигурация включает RESET_WEBHOOK_ON_START=true: перенос на polling
произойдёт на новом хостинге после успешной проверки токена.
Остановите прежний сервис бота, чтобы он не устанавливал webhook заново.
Данные на прежнем сервере не переносятся автоматически: при наличии целей
скопируйте его data.json на постоянный диск до первого рабочего запуска.
Тесты в процессе сборки используют временные файлы и не требуют BOT_TOKEN.
Публикация среды разработки Codex не разворачивает сервис в Render.

WEBHOOK И POLLING

Webhook и polling одновременно не работают. По умолчанию программа сообщает
о конфликте. После выбора нового хостинга RESET_WEBHOOK_ON_START=true
разрешает отключение старого webhook при запуске, сохраняя очередь
обновлений (drop_pending_updates=False). Без этого флага webhook не меняется.
Проверка --check не меняет webhook даже при включённом флаге.
Не запускайте два экземпляра polling с одним токеном.

ХРАНЕНИЕ И СЕТЬ

Старый формат data.json поддерживается, накопления не обнуляются.
Запись атомарная; повреждённый файл вызывает понятную ошибку и сохраняется
для восстановления. Делайте резервные копии DATA_FILE.
Токен, ранее опубликованный в коде, следует перевыпустить у @BotFather
и сохранить в BOT_TOKEN. Удаление из текущего файла не удаляет его из истории Git.
HTTPS_PROXY/HTTP_PROXY и системное хранилище доверенных CA поддерживаются;
проверка TLS остаётся включённой. Нужен доступ к api.telegram.org.
Ошибка загрузки необязательной картинки не отменяет начисление.

ПРОВЕРКИ

python -m unittest discover -s tests -v
Тесты используют временные данные и подменённый Telegram-транспорт:
команды, настройки и отмена, валидация чисел, защита от повторного начисления,
конкурентные сообщения, сохранение/сброс, сбои записи, миграция данных,
напоминания и корректное завершение процесса. Реальные сообщения не отправляются.
